A27 API Kullanım Koşulları

API erişimi, anahtarlar ve sorumlu kullanım

Şeffaflık notu: Anahtarların geçerliliği, kota, fiyatlandırma ve kullanılabilir modeller gerçek backend ayarlarına bağlıdır; doğrulanmamış limitleri kesin hizmet taahhüdü olarak sunmayın. Bu belge, gerçek hizmet yapılandırmasıyla birlikte değerlendirilmelidir.

1. Kapsam ve amaç

A27 API erişimi; erişim anahtarlarının güvenli tutulması, hız sınırlarına uyulması ve hizmetin kötüye kullanılmaması koşullarına bağlıdır.

2. Uygulama ve sorumluluklar

Anahtarlar parola gibi gizli tutulmalı, istemci tarafında herkese açık kod içine gömülmemeli ve sızıntı şüphesinde iptal edilmelidir. Yetkisiz erişim denemeleri, limit aşımı veya hizmeti bozma girişimleri engellenebilir.

3. Kullanıcıların dikkat etmesi gerekenler

Uç nokta adresleri, kimlik doğrulama yöntemi, kota, fiyatlandırma, veri işleme ve sürüm desteği ancak çalışan API yapılandırmasıyla doğrulandıktan sonra yayımlanmalıdır.

4. Şeffaflık ve güncellemeler

Hizmetler, entegrasyonlar veya yürürlükteki kurallar değiştiğinde bu sayfa güncellenmelidir. Son güncelleme tarihi, yürürlük tarihi ve sorumlu işletmeci bilgileri yayına çıkmadan önce eklenmelidir.

5. Başvuru ve iletişim

Başvuru için İletişim ve Başvuru sayfasını kullanın. Veri koruma talepleri için ayrıca KVKK Aydınlatma Metni incelenmelidir.

6. Anahtar güvenliği

API anahtarlarını parola gibi koruyun. Anahtarları kaynak koda, herkese açık repoya veya istemci tarafında herkesçe okunabilen alana gömmeyin. Gereksiz erişimi iptal edin ve sızıntı şüphesinde anahtarı yenileyin.

7. Kota ve hız sınırları

İstek limitleri sağlayıcıya, plan türüne ve hizmet durumuna göre değişebilir. Limit aşımında otomatik tekrar denemelerini sınırlandırın; sistemi aşırı istekle zorlamayın ve hata yanıtlarını yönetin.

8. Veri minimizasyonu

API isteklerine yalnızca gerekli verileri koyun. Uygulamanızın son kullanıcılarına hangi verileri hangi sağlayıcıya ilettiğinizi ve kendi saklama uygulamanızı açıkça belirtin.
